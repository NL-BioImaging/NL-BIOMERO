## Production upgrade plan

**From:** NL-BIOMERO 1.7.1-beta.5 (a prerelease with some features not in 1.7.x, without the 1.7.3–1.7.5 OMERO.web security fixes). Record the exact stack and importer tags first. 1.8.0 brings production back onto the stable line.
**To:** NL-BIOMERO 1.8.0 (`omeroserver`, `omeroweb`, `omeroworker`, `biomero` at `1.8.0`); `cellularimagingcf/biomero-importer:1.5.0`; biomero-converter v0.2.5 for preprocessing routes.

### Before

- Schedule the downtime on a Friday evening or at the weekend, agreed with the administrators.
- Warn users in advance by e-mail to all users (`omero admin email --everyone`, which needs the OMERO mail settings) with the window and a deadline for submitting workflows; send a second warning shortly before.
- Just before stopping, check that nothing is active (running workflows, imports, script jobs, Slurm jobs). If something is, warn again or move the window.
- Let running workflows and imports finish; confirm nothing is queued in BIOMERO or the importer.
- Full backup: OMERO database, BIOMERO database (including importer tracking), OMERO binary repository (or confirm its snapshot policy), Metabase application data, and deployment material (private environment file, site config, secrets). Verify it: checksums, a test listing or restore, and a confirmed off-host copy.
- Record the current state: image tags and digests, deployment repository commit, current Slurm configuration and admin settings, container and service status.
- Confirm every 1.8.0 image is published before stopping anything.

### Changes needed

- Pass the new worker settings: OMERO credentials and the feature flags (detached, shallow, remote shallow), plus active-workflow and supervisor settings if detached workflows are used.
- Give the importer the group-mapping file and the shallow flags; keep its existing container-storage volume.
- Pass the viewer and feature flags to OMERO.web.
- Confirm OMERO.web and the worker share one Slurm configuration file.
- Update the site converter configuration to biomero-converter v0.2.5 with OME-Zarr 0.4 output.
- Shared Slurm INI: `ssh_recovery_timeout` (default 900); a lock command (`slurm_lock_cmd`) if the cluster has no `flock`; `sacct` available; update the site workflow versions in use (for example Cellpose v1.4.1).
- Keep production's processed-data folder unchanged.
- Keep the public-HTTPS API discovery settings and their readiness check.
- Re-validate any backup or restore integration against the changed deploy tooling.

New features: **production enables all of them at 1.8.0**; they were tested in acceptance.

- Detached workflows on; shorten the OMERO session timeouts afterwards.
- Shallow OME-Zarr storage and remote shallowing on (`remote_shallow_zarr = true` in the Slurm INI); include the shallow stores in the backup review.
- OME-Zarr Viewer on: two Nginx locations, read-only storage access and the metadata size limit.
- SSH recovery on (default, 900 s).
- Admin settings (image pulls via sbatch, Zarr v3 input, skip original-pixel comparison, Plate Mask Preview): as configured in acceptance.

### Upgrade steps

1. Put the site into maintenance; confirm users see the maintenance page.
2. Disable autostart units, then stop: logging stack (optional), importer, BIOMERO worker, OMERO workers, OMERO.web, Metabase, OMERO.server, databases.
3. Pull the 1.8.0 images and importer 1.5.0.
4. Apply the configuration changes above.
5. Start: databases, OMERO.server, OMERO.web, Metabase, OMERO workers, importer, then the BIOMERO worker once the importer is live; then the front end, logging stack and autostart units.
6. Migrations: the importer adds one column to its tracking database at startup. OMERO schema unchanged; BIOMERO workflow histories are read unchanged.
7. In OMERO.web as admin: **Slurm Init**, then **Slurm Check Setup**; resolve `flock`/`sacct` warnings.
8. Leave maintenance only after the readiness checks pass, including HTTPS API discovery.
9. Optional, later: dry-run **Refresh OMERO Metadata** for older results.

### Checks after the upgrade

- All containers run their expected tags; autostart units active; no restart loops.
- Log in through the public URL; API discovery returns public HTTPS links.
- Import a small file through the importer and see it in OMERO.
- Run a small workflow end to end on Slurm; results imported.
- If scripts report "No processor available" after a worker restart: re-enable `Processor-0` in IceGrid admin (known issue #117).
- Viewer opens a registered OME-Zarr image; a detached workflow keeps running after logging out; a shallow result is created.
- Dashboards and logs pages load; no new errors in OMERO.web, BIOMERO worker and importer logs.

### Rollback

- Roll back if login, import or a basic workflow fails and can't be fixed in the window, or if data integrity is in doubt.
- Only images or config changed: back to maintenance, restore the recorded tags and configuration, redeploy, re-run Slurm Init.
- Databases changed: restore both databases from the pre-upgrade backup and revert the configuration. Work done in the upgrade window is lost and must be redone; orphaned files may need cleanup. Verify with the same smoke test.
