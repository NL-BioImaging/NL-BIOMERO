# NL-BIOMERO 1.9.0-beta.1: scope and coordination

Status on 26 November 2026: **in preparation**. Nothing in the scope is merged
or prereleased yet, so this branch carries no version bumps or pins. The draft
release PR `Release 1.9.0-beta.1 (coordination)` is the coordination point:
whoever picks up the release (person or agent) reads this file first, then the
release steps in [`omero-biomero-expert`](../../.agents/skills/omero-biomero-expert/SKILL.md#prerelease-coordination-and-acc-handoff),
and keeps this file current.

1.9.0-beta.1 is the first prerelease after stable
[1.8.0](https://github.com/NL-BioImaging/NL-BIOMERO/releases/tag/v1.8.0); its
release notes compare with 1.8.0.

## Coordinator checklist

Follow the release steps in
[`omero-biomero-expert`](../../.agents/skills/omero-biomero-expert/SKILL.md#prerelease-coordination-and-acc-handoff)
in this order; tags, prereleases, merges, stack restarts and deployments each
need the maintainer's explicit authorization.

### Before preparing

- [ ] Third-party dependencies of every component: newer versions and
      advisories (`pip list --outdated`, `pip-audit` in a fresh environment,
      front-end packages, container base images) and open Dependabot alerts per
      repository. Raise pins in the components' own PRs; file a board story
      per major upgrade.
- [ ] The stack's own pins, each with a recorded decision (take up and test in
      acceptance, or leave for later):
  - [ ] biomero-converter: `0.2.5` in `web/biomero-config.json`; latest is
        v0.5.0. Taking it up changes the conversion output (1.8.0 ships
        OME-Zarr 0.4 from the default routes) and is likely needed for the
        DICOM option (OMERO.biomero#52).
  - [ ] Workflow versions in the Slurm INIs (`web/slurm-config.ini`,
        `biomeroworker/slurm-config*.ini`). The ImageJ nuclei segmentation
        workflow stays at v1.12.10 on purpose (comment at the pin); leave it
        unless that reason has gone.
  - [ ] `.env` / `.env.shared` pins (viewer, Zarr pixel buffer, OMERO.forms,
        label2rois), OME base images, Postgres, the Metabase digest (unless
        OMERO.biomero#53 removes Metabase) and the unpinned `nginx:alpine`.
  - [ ] Core `full` extra floor: already raised to the stable importer 1.5.0 on
        core main (de3e197); it ships with the next core prerelease.
- [ ] List every open board item with Release = `1.9.0` before each component
      prerelease; a component is ready only when no open item still needs a
      change in it. Move items out only with the maintainer's agreement.

### How this release changes the upgrade procedure

- [ ] NL#71 changes the bind-mounted Nginx configuration: the proxy keeps
      running through maintenance, so recreate it once
      (`docker compose up -d --force-recreate <proxy>`) and check through the
      public route (a viewer store file returns 200).
- [ ] OMERO.biomero#53: if Metabase is removed, its service, environment variables, proxy
      location and data are retired; say what happens to existing dashboards
      and whether its data is kept for a rollback.
- [ ] NL#70: a new optional service and its flags; say what an upgrading site
      must add and that it stays off without them.
- [ ] OMERO.biomero#56 and #52: new INI or converter settings, and whether Slurm Init must run.
- [ ] Core: whether `init_slurm` must run, whether stored data or views change,
      and whether a downgrade still works.
- [ ] NL#132: new deploy and admin-script commands change how the upgrade itself
      is run; update the upgrade docs with them.

### Acceptance

- [ ] Local acceptance of the exact release branch build against
      NL-BIOMERO-Local-Slurm (or -GPU for OMERO.biomero#56), recorded in
      `plans/releases/1.9.0-beta.1-local-acceptance.md`.
- [ ] Squash-merge on the maintainer's acceptance; publish `v1.9.0-beta.1`
      (prerelease) on its own authorization; verify every stack image is
      pushed before handing tags to ACC.
- [ ] ACC plan below written and handed over; at handoff check ACC's deployed
      image tags and its configuration pins (converter, workflow versions).
- [ ] ACC loop: poll ACC's deploy branch for `[finding]`, `[report]` and
      `[verdict]`, file findings (NL-BIOMERO issue plus component sub-issue),
      fold blocking fixes into the next beta with its own release PR, repeat
      until ACC accepts.

### Stable 1.9.0 (separate PR `Release 1.9.0`)

- [ ] Stable releases of every prerelease dependency, in dependency order;
      no prerelease left in any requirement, pin or helper image.
- [ ] ACC stable check: smoke on the stable build, version check, rows for code
      changed since the accepted beta; no new checks.
- [ ] `plans/releases/1.9.0.md` with the production plan: upgrade from
      production's running version, backup, steps, rollback rule and decision
      time, post-upgrade checks, and the upgrade-procedure changes above.
- [ ] Drift check: compare the acceptance and production branches of the
      private deployment repository since the commits recorded in the 1.8.0
      plan; describe differences generically.
- [ ] The two user mails from
      [user-mails.md](../../.agents/skills/omero-biomero-expert/references/user-mails.md).
- [ ] image.sc announcement draft as a reply in the NL-BIOMERO thread.

To be written when the scope is merged. Expected rows per scope item:

- OMERO.biomero#53 dashboards: workflow and import overviews show the same information as
  the Metabase dashboards did, for users and admins, after an upgrade from
  1.8.0 with existing history.
