  `BIOMERO_REMOTE_SHALLOW_ZARR` aligned with the existing enabled demo setup.
  Explicitly exercise shallow storage OFF: neither metadata nor the workflow
  setting may override full-result storage.
- Use helper image `cellularimagingcf/biomero-shallower:0.1.0-beta.9` with
  helper/receipt/importer-trust version `0.1.0b9`. Update all applicable INI,
  environment and Compose examples together. Install the new helper through
  Slurm Init and confirm Check Setup is READY before remote use. A changed
  Docker tag alone does not update an already installed SIF.
- The optional per-model setting is stored as
  `[UI] original_pixels_not_required_workflows`, a JSON workflow-name list.
  Missing/empty/`[]` leaves this shortcut disabled. Enable only for workflows
  whose original image pixels need not be returned, such as known label-producing
  workflows. It avoids original-pixel comparison work; managed input pixels remain
  unchanged. Runtime changes apply to new runs, not a run already in progress.
- Usable RO-Crate output declarations are interpreted automatically while shallow
  storage is enabled, independent of that switch. No extra approval/allowlist flag
  is introduced. Future Bilayers presets are not part of this release.
- SSH recovery remains 900 seconds when missing/blank; explicit `0` disables it.
  No new SSH feature flag is required. Keep the setting INI/admin-managed rather
  than injecting an environment override that masks saved admin values.
- Preserve the existing per-workflow OME-Zarr v3 choice and v2 default. Fingerprint
  profile changes do not require converting v2 canonical sources to v3.

### Result handling and canonical fingerprints

| Setup | Expected result |
| --- | --- |
| Shallow OFF, even with usable crate and model switch ON | Full self-contained results; no deduplication-only hash/prune |
| Shallow ON, usable run/source-bound label output declaration, switch OFF | Automatic `ro-crate-output`; known input reused, labels/results/sidecars retained |
| No usable declaration, model switch ON, unambiguous input/artifact binding | `workflow-setting`; skip original-pixel comparison and retain derived results |
| Neither shortcut | `pixel-comparison` using the stored current canonical fingerprint and compatible returned pyramid level; mismatches retain full results |

- [ ] Verify the four rows on v2 and v3, with both execution modes and local/remote
  result processing represented. Original input files and object IDs remain unchanged.
- [ ] Verify canonical-cache reuse. Only missing/stale profiles refresh against
  the actual managed canonical backing store. A remote helper without a current
  fingerprint keeps the result full for local importer handling; subsequent runs
  reuse the refreshed record. No fresh export/copy/reimport solely for cache refresh.
- [ ] Retain additional derived images, changed/new labels and measurement CSVs,
  including files not enumerated in the crate. Wrong-run/wrong-source/root-only
  declarations must not authorize an incorrect source link. Explicit inventories
  of files that pruning would remove keep the artifact full and crate unchanged.
- [ ] Verify image/Plate field mappings, dimensional and transform compatibility,
  complete C/Z/T coverage, and label identity. Selected-level equality is exact at
  that resolution; it is not a proof of full-resolution equality or perceptual matching.
- [ ] Repeat clean large import with mandatory provenance and controlled fresh-export
  identity verification. Do not use manual annotation repair to make a run pass.

Bare-label-only stores without enclosing image arrays are not newly reconstructed
by this change. Do not treat that unimplemented shape as a promised feature.

### Additional SSH checks

Use isolated test connections/jobs. Never stop a shared SSH service or remove
recovery evidence. Record the actual fault phase and preserve original workflow,
task, allocation and output IDs.

- [ ] **Running allocation continuity, inline and detached:** interrupt SSH while
  the original analysis is RUNNING; restore within the configured window. Resume
  the same allocation, retrieve its result and import once. Verify Slurm accounting
  independently, plus successful OMERO heartbeats and mandatory provenance.
- [ ] **Silent channel opening/safe-read stall:** rerun the private-connection
  reproducer against the published runtime. Record native detection time separately
  from the recovery window. Do not promise a universal deadline for every SSH phase.
- [ ] **Submission response lost after acceptance:** reconcile the original sbatch
  allocation instead of resubmitting; cover analysis and relevant helper/converter
  jobs. Delayed accounting must not cause duplicate work.
- [ ] **Result ZIP interruption:** restart downloads from byte zero, publish only
  complete verified data and never repeat successful analysis or import partial files.
- [ ] **Window exhaustion and zero:** a short positive window deliberately ends the
  attempt in FAILED while preserving IDs/receipts/results. Restoring SSH does not
  resurrect it. Explicit zero retains single-attempt behavior; permanent errors fail
  clearly. Healthy elapsed processing is not itself an outage.
- [ ] **Restart and cancellation:** restart only an isolated detached processor;
  eligible unfinished work resumes from persisted identity without duplicate
  submission/import. Intentional cancellation and terminal attempts remain terminal.

The remaining Paramiko acknowledgement-wait behavior is already reported in
[upstream #319](https://github.com/paramiko/paramiko/issues/319). A wait by itself
is not an extra release blocker or a reason to implement another SSH framework.

### Terminal-event persistence: promotion blocker

The earlier ACC administrative cancellation inconsistency was initially a scoped
follow-up. Local acceptance has now demonstrated ordinary lifecycle impact:

1. A detached fixture workflow failed before allocation because its private script
   repository was configured without Init. Independent PostgreSQL and native reads
   showed source versions 0–3, while the projection recorded FAILED after handling
   a version-4 WorkflowFailed event. No allocation existed at that point.
2. Normal Slurm Init, with its default analytics rebuild enabled, was then run.
   The detached processor automatically resumed that same workflow and started an
   allocation. No operator replay, repair or resubmission of that UUID occurred.

This violates the requirement that a terminal attempt remain terminal. Promotion
is held for a focused core persistence fix and new published component pins.
The investigation identified three inline-listener cache-miss reads that close a
borrowed shared SQLAlchemy session while the producer event is still pending;
regressions must verify source durability, projection rebuild and no resumed
terminal attempt. Do not classify this as an upstream library defect.

Preserve the original evidence without repairing/replaying the failed workflow
or ACC's two earlier terminal records. Use new isolated fixtures for the fix's
independent source/projection and lifecycle checks. Previously passing SSH and
pixel cases remain evidence for their tested version, not acceptance of the
forthcoming corrected candidate.
